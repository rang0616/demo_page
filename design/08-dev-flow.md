# 08. 개발 플로우

상태: 확정 (ADR-035·036, ADR-037). 버전 로드맵(3장)은 초안입니다.

## 1. 브랜치 전략 (ADR-035)

| 이름 | 용도 | 규칙 |
|------|------|------|
| `main` | 완성본만 둡니다. GitHub Pages가 여기를 배포합니다. | 직접 커밋하지 않습니다. 설계 기준선 커밋과 최종 완성본 머지만 허용합니다. |
| `v0.1`, `v0.2`, ... | 중간 버전 작업 브랜치입니다. 각 버전은 직전 버전 브랜치에서 분기합니다. v0.1은 `main`에서 분기합니다. | 한 번에 하나만 엽니다. 로컬에서만 확인하고 `main`에는 머지하지 않습니다. |
| 태그 `v1.0.0` | 완성본을 `main`에 머지한 뒤 `main`에 붙이는 릴리스 태그입니다. | 중간 버전에는 태그를 붙이지 않습니다. |

- 설계 문서만 바꾸는 변경도 `design/` 전용 브랜치에서 PR로 올립니다. 예: `design/xxx`
- 중간 버전은 로컬에서 확인합니다. `main`에는 모든 버전이 끝난 완성본만 머지합니다. (ADR-037)

### 버전 단위
- 한 버전은 설계 문서의 한 묶음을 구현하는 단위입니다.
- 중간 버전 번호는 `v0.x`로 올립니다. `main`에 머지하는 최종 버전은 `v1.0.0`입니다. (ADR-037)

## 2. 작업 절차

1. **설계 확인**: 버전 목표와 완료 조건이 `design/`에 있는지 확인합니다. 없으면 먼저 문서를 고칩니다. (헌법 3조)
2. **브랜치 생성**: `main`에서 `v0.x` 브랜치를 만듭니다. (사용자 요청 시에만)
3. **구현**: 작은 커밋으로 나눕니다. 커밋 메시지는 한 줄 요약입니다. (사용자 요청 시에만)
4. **로컬 확인**: 저장소 루트에서 `python3 -m http.server -d src`를 실행하고 `http://localhost:8000`을 엽니다. `file://`로 열면 암호문을 읽을 수 없습니다. 체크리스트는 `CLAUDE.md` 검증 방법을 따릅니다.
5. **리뷰**: 설계와 코드 리뷰는 Opus 5.5 검토용 서브에이전트(읽기 전용)로 수행합니다. 지적 사항은 검토해서 반영합니다.
6. **중간 버전 완료**: 로컬 확인과 리뷰를 마치면 해당 `v0.x` 브랜치는 그대로 둡니다. 다음 버전 브랜치는 이 브랜치에서 분기합니다.
7. **최종 완성 PR**: v0.5까지 끝나면 최종 브랜치를 `main`으로 PR합니다. 설명에는 전체 버전 목록, 로컬 확인 결과, 관련 ADR을 적습니다.
8. **머지**: 사용자가 GitHub에서 직접 머지합니다. 방식은 **merge commit**을 씁니다. squash는 쓰지 않습니다. 버전 이력이 그대로 남기 때문입니다.
9. **태그**: 머지 후 `main`에서 `v1.0.0` 태그를 만들고 푸시합니다. 사용자 요청이 있을 때만 실행합니다.
10. **변경 이력**: 설계 변경이 있었을 때만 `design/CHANGELOG.md`에 기록합니다. (5장 참조)

- 커밋, 푸시, PR 생성, 태그 생성은 `CLAUDE.md`의 Git 규칙에 따라 사용자가 요청할 때만 실행합니다.

## 3. 버전 로드맵 (초안)

| 버전 | 목표 | 완료 조건 |
|------|------|-----------|
| v0.1 | 잠금 화면과 복호화 | 정답 입력 → 복호화 → 다음 화면. 틀린 답은 격려 문구, 빈 입력은 안내. 답 정규화(ADR-025). 암호문 도구가 전체 본문(바우처와 편지, ADR-026)을 암호화. 다음 화면은 임시 화면으로 둡니다. 공통 스타일 기반(CSS 변수, Pretendard와 나눔손글씨 글꼴). 확인 중 "열고 있어…" 표시와 버튼 잠금. 새로고침 시 잠금부터(v0.3부터는 안내 화면부터, ADR-057). |
| v0.2 | 선물 열기 연출과 바우처 | 상자 탭 → 효과음(ADR-027) → 바우처 8개 항목과 로고 표시(ADR-048). 모션 감소 설정 대응. 임시 화면을 대체합니다. |
| v0.3 | 안내 화면, 편지와 센터 안내 | 안내 화면(첫 화면, ADR-057): 안내 문구와 시작 버튼, 잠금 화면 진입, 새로고침 시 안내 화면부터. 안내 제목의 이모지는 `aria-hidden`, 모든 버튼에 "뾱" 효과음(상자 버튼 제외, ADR-058). 잠금 화면 안내 두 줄과 질문 변경, 입력창 이름은 질문만(ADR-059). 편지 기본 펼침과 접기(라벨 "접어두기"/"펼쳐보기", ADR-060). 센터 소개 문구와 사전 예약제 안내. 주소 복사(성공 "주소를 복사했어!", 실패 "복사가 안 됐어. 주소를 길게 눌러서 복사해 줘."와 선택 가능한 주소). 네이버 지도 링크(새 탭, ADR-060). 접기와 주소 복사 버튼에도 "뾱" 효과음. |
| v0.4 | 예약 안내와 메타 | 예약 안내 문구(ADR-029, 02 기준). 메타 정보(`<title>`, og, noindex, ADR-030). og:image와 favicon은 두지 않습니다. |
| v0.5 | 배포 준비 | Pages Source 전환과 첫 배포 확인(ADR-050, 워크플로 `pages.yml`은 v0.1에서 작성). 루트 데모 `index.html` 제거(ADR-023). 루트의 원본 로고 파일 제거(`src/img/`로 옮긴 뒤, ADR-048). Pages 소스 확인. 배포 후 점검: 소스 보기에서 정답 없음, 카카오톡 인앱 브라우저에서 열기. |

- v0.1 완료에는 루트 `package.json`(type: module) 생성, 4-1의 `node --test tests/*.test.mjs`와 `node tools/encrypt.mjs --self-test` 통과가 포함됩니다.

### 전 버전 공통 완료 조건
- 390px 폭에서 가로 스크롤이 없습니다.
- 콘솔 에러가 없습니다.
- 정답과 평문 편지가 `src/` 안에 없습니다. 편지 본문은 암호문으로만 있습니다.
- 확대 축소를 막지 않습니다.
- 로컬 확인 결과를 PR에 기록합니다. 확인하지 못한 항목은 명시합니다.

## 4. 커밋과 PR 규칙

- 커밋 전에 `git diff --cached`로 다음을 확인합니다.
  - `design/private/`가 포함되지 않았는지
  - 정답 문자열, 토큰, 비밀번호가 없는지
  - `tests/`에 실제 정답이 없는지 (예시 날짜만 사용, ADR-025)
- PR 설명에는 버전 목표와 완료 조건 충족 여부, 로컬 확인 결과, 설계 변경이 있으면 ADR 번호를 씁니다.

## 4-1. 검증 (ADR-038, ADR-039)

- 자동: `node --test tests/*.test.mjs`로 정규화와 암호 왕복 테스트를 돌립니다. `node tools/encrypt.mjs --self-test`로 암호 왕복을 확인합니다.
- 수동: 로컬 서버에서 잠금 해제 흐름을 한 번 실행합니다. 틀린 답, 빈 입력, 네트워크 오류(파일 이름을 잠시 바꿔 확인)를 포함합니다.
- 두 자동 검사 결과와 수동 확인 결과를 PR 설명에 적습니다.

## 4-2. 일정과 진척 (ADR-052)

- 일정은 `schedule/`에서 관리합니다. 전체 현황과 계산 규칙은 `schedule/README.md`, 일별 작업은 `schedule/YYYY-MM-DD.md`입니다.
- 작업을 마치면 체크박스와 진행률을 갱신합니다. 계획이 바뀌면 일별 파일의 "변경 이력"에 이유와 함께 남깁니다.

## 5. 변경 이력 규칙 (ADR-036)

- 설계 변경이 있을 때만 `design/CHANGELOG.md`에 항목을 추가합니다. 구현 이력은 기록하지 않습니다.
- 항목 형식은 ADR-036을 따릅니다: 날짜, 버전, 변경, 이유, ADR, 커밋.
- 커밋 해시는 커밋 후에 기록합니다. 해시를 알 수 없으면 `-`로 두고, 나중에 채웁니다.

## 6. 배포 규칙

- 배포 주소: `https://rang0616.github.io/demo_page/`
- 배포는 `.github/workflows/pages.yml`이 합니다. `main`에 push되면 단위 테스트(`node --test tests/*.test.mjs`)를 돌리고, 통과하면 `src/`를 그대로 배포합니다. 테스트가 실패하면 배포되지 않습니다. (ADR-050)
- `main`에 머지되는 것은 최종본뿐입니다. 배포 후 실제 주소에서 잠금 해제를 한 번 확인합니다. 반영에는 몇 분 걸릴 수 있습니다.
- 배포 전 점검 순서:
  1. 루트 데모 `index.html` 제거 여부 확인 (ADR-023)
  2. 저장소 Settings → Pages → Source가 "GitHub Actions"인지 확인
  3. 소스 보기에서 정답이 없는지 확인. 편지는 ADR-023에 따라 공개를 허용합니다.

## 7. 미확정 항목

- 버전 완료 조건은 사람이 체크리스트로 확인합니다. 정규화와 암호 왕복은 4-1의 자동 검사로 확인합니다.
- v0.5 완료 후 `main`에 머지하는 최종본이 `v1.0.0`입니다. (ADR-037)

# 05. 아키텍처

상태: 초안

## 기술 선택

| 영역 | 선택 | 이유 |
|------|------|------|
| 호스팅 | GitHub Pages (정적) | 현재 저장소를 그대로 쓸 수 있고 무료입니다 |
| 구조 | HTML, CSS, Vanilla JS | 규모가 작고, 빌드 없이 관리합니다 |
| 잠금 | 브라우저에서 답을 확인해 본문을 복호화 | 잠금 전에는 본문이 암호문으로만 존재합니다 |
| 암호 | Web Crypto API (PBKDF2 + AES-GCM) | 브라우저 기본 기능이라 외부 라이브러리가 필요 없습니다 |

## 잠금 방식

### 원리
1. 편지, 바우처, 센터 정보 같은 **본문 데이터를 답으로 암호화**해서 파일에 넣습니다.
2. 윰댕이 질문에 답을 입력하면, 브라우저가 그 답으로 키를 만들어 본문을 복호화하고 화면에 그립니다.
3. 틀린 답이면 복호화에 실패하고, 격려 문구를 보여 줍니다. 횟수는 세지 않습니다.

### 한계 (반드시 인지)
- **답이 날짜(월·일)라면 후보가 365개뿐입니다.** 암호문을 가진 사람은 모든 날짜를 몇 초 만에 시도해 풀 수 있습니다.
- 이 잠금은 **가볍게 훑어보는 것을 막는 수준**입니다. 악의적인 사람을 막는 보안이 아닙니다.
- 이 한계는 윰댕 한 명을 상대로 하는 깜짝 선물이라는 목적에서는 실질적으로 문제가 되지 않을 가능성이 높지만, 결정은 휘님이 해야 합니다. (`06-decisions.md` ADR-004, `07-open-questions.md` Q2)

### 보강 옵션 (선택)
- A. 그대로 사용 (가볍게 막는 수준)
- B. 답 외에 고정 문구를 더해 키를 만든다. 소스를 보는 사람은 여전히 풀 수 있지만, 추측 한 번으로 풀리는 것은 막습니다.
- C. 질문을 더 어렵게 바꾼다. (예: 날짜에 연도 포함). 답이 길어지면 윰댕에게도 부담이 됩니다.

## 암호문 생성

- 암호문은 **한 번 만들어서 파일에 넣는** 방식입니다. 생성 스크립트 하나(`tools/`)가 필요합니다.
- 헌법의 "빌드 없음" 원칙과 충돌하지 않도록, 이 스크립트는 **본문이 바뀔 때만 실행하는 일회성 도구**로 둡니다. 배포 과정에 끼지 않습니다.
- 편지를 고치면 암호문을 다시 만들어야 합니다. 이 절차는 `05-architecture.md`에 적어 둡니다.

## 파일 구성 (제안)

```
index.html          # 잠금 화면과 공개 화면 (CSS, JS 인라인)
data/               # 암호화된 본문 (생성 결과물)
tools/              # 암호문 생성 스크립트 (일회성)
design/             # 설계 문서 (SoT)
CLAUDE.md           # 헌법과 작업 규칙
.claude/            # Claude Code 설정과 커맨드
리스파이어랩.png     # 로고 (바우처에 쓰는 경우에만)
```

## 배포

1. 본문 변경 시: 원문을 고친다 → `tools/`로 암호문 재생성 → 로컬 확인
2. 사용자 승인 후 `main`에 푸시
3. GitHub Pages 반영을 확인하고, 실제 URL에서 잠금 해제를 한 번 테스트

## 저장소 공개 범위

- 현재 저장소는 공개입니다. 암호문과 페이지가 누구나 볼 수 있는 상태가 됩니다.
- 비공개 저장소로 바꾸면 GitHub Pages 공개 방식이 달라질 수 있습니다. 결정은 Q3.

## 접근성·성능

- 확대 축소를 막지 않습니다.
- 이미지에는 `alt`를 씁니다. (로고를 쓰는 경우)
- 파일 크기는 200KB 이하를 목표로 합니다.

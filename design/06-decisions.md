## ADR-025. 정답은 숫자로 정규화해 비교한다
- 날짜: 2026-10-15
- 상태: 확정
- 배경: 잠금 화면과 암호화 도구가 같은 키를 만들어야 합니다. 허용 표기 규칙이 없으면 두 쪽이 다르게 구현됩니다.
- 결정:
  1. 입력에 NFKC를 적용한 뒤, ASCII `[0-9]+`의 연속 구간을 숫자 묶음으로 추출합니다. 그 밖의 글자(공백, 구두점, "월", "일", 그 밖의 비 ASCII 숫자 포함)는 묶음 사이의 구분자이며 값으로 쓰지 않습니다.
  2. 숫자 묶음이 3~4자리 하나이면 뒤 2자리를 일, 앞 1~2자리를 월로 봅니다. 3자리에서 앞 1자리가 월입니다(`115`는 1월 15일). 예: `305`, `0305`, `1116`.
  3. 숫자 묶음이 두 개이면 첫 번째를 월, 두 번째를 일로 봅니다. 예: `3월 5일`, `3/5`, `3.5`.
  4. 그 밖의 경우(숫자 묶음이 셋 이상, 4자리 연도 포함 등)는 틀린 답입니다.
  5. 월은 1~12, 일은 1~31이어야 합니다. 범위를 벗어나면 틀린 답입니다. 월별 일수는 보지 않으므로 `2/31`은 허용됩니다.
  6. 결과를 `MMDD` 두 자리 두 쌍으로 맞춘 문자열을 키 생성 입력으로 씁니다. 정답 값은 `design/private/`에만 있습니다.
- 테스트 표(구현 시 검증, 예시 날짜는 실제 정답과 무관한 값입니다): `3월 5일`→0305, `3/5`→0305, `3.5`→0305, `305`→0305, `0305`→0305, `3 5`→0305, `2026년 3월 5일`→틀림, `13/1`→틀림
- 영향: `01-experience-flow.md`, `02-content.md`, `05-architecture.md`, 암호화 도구

## ADR-026. 암호문과 평문의 포맷을 고정한다
- 날짜: 2026-10-15
- 상태: 확정 (문단 안 줄바꿈의 화면 표시는 ADR-060에서 보완)
- 배경: 암호화 도구와 페이지가 같은 파일 구조를 알아야 합니다.
- 결정:
  - KDF: PBKDF2, 해시 SHA-256, 반복 600,000회, salt 16바이트(무작위, base64)
  - 암호: AES-256-GCM, iv 12바이트(무작위, base64), 인증 태그는 WebCrypto 기본 방식으로 암호문에 붙입니다.
  - `docs/data/letter.enc.json` 형식:
    ```json
    {"v":1,"kdf":{"name":"PBKDF2","hash":"SHA-256","iter":600000,"salt":"<base64>"},"cipher":{"name":"AES-GCM","iv":"<base64>"},"ct":"<base64>"}
    ```
  - 평문(JSON, 암호화 전): `{"voucher":{...바우처 표 8개 항목...},"letter":["사랑하는 윰댕에게 ❤️", "문단1", "문단2", "...", "With all my love & support."]}`
    - `letter` 배열의 첫 항목은 호칭, 마지막 항목은 맺음말입니다. 나머지는 문단입니다. 줄바꿈은 문단 단위입니다.
  - 센터 정보는 평문이어도 되므로 공개 HTML에 둡니다. 소스 보기로 선물 일부가 드러나는 것은 허용합니다.
  - PBKDF2의 password는 ADR-025 결과 `MMDD`의 UTF-8 바이트입니다. 파생 키는 256비트입니다. AES-GCM에는 AAD를 쓰지 않습니다. base64는 표준 방식이며 패딩을 포함합니다.
  - 평문 `voucher`는 8개 행을 키-값 객체로 둡니다. 키 이름은 행 순서대로 `label`, `badge`, `title`, `subtitle`, `recipient`, `occasion`, `center`, `careType`입니다.
  - 화면에 그릴 때는 `textContent`만 씁니다. `innerHTML`로 편지 내용을 넣지 않습니다.
- 영향: `05-architecture.md`, 암호화 도구, 페이지 스크립트

## ADR-042. 입력 출처와 검증 세부를 고정한다
- 날짜: 2026-10-15
- 상태: 확정
- 배경: 바우처 값의 출처, 편지 분리 규칙, 평문 검증, 셀프 테스트 동작이 정해져 있지 않았습니다.

  - 바우처 8개 값은 `tools/voucher.json`에서 읽습니다. 02의 바우처 표와 같아야 하며, 바꿀 때는 두 곳을 함께 고칩니다.

## ADR-051. v0.1 코드 리뷰 지적을 반영해 세부 규칙을 정한다
- 날짜: 2026-10-15
- 상태: 확정
- 배경: Opus 5.5 코드 리뷰(Blocker 0, Major 2, Minor 14)에서 설계 보강이 필요한 항목이 나왔습니다.

  - 테스트: 잘못된 base64, ct 길이 부족, 암호 이름 불일치, 평문 JSON 아님, 편지 항목 타입 오류, `v` 누락, 정규화 추가 입력, 절 경계 파싱을 추가합니다.
- 영향: `01-experience-flow.md`, `04-design-system.md`, `05-architecture.md`, `docs`→`src`의 코드, `tests/`, `tools/encrypt.mjs`, `.gitignore`

## ADR-058. 안내 문구를 이모지와 함께 바꾸고, 모든 버튼에 "뾱" 효과음을 넣는다
- 날짜: 2026-10-15
- 상태: 확정 (ADR-057의 안내 문구와 "장식 없음", ADR-028의 허용 이모지, ADR-055의 효과음 구성을 일부 대체)
- 배경: 휘님의 피드백입니다. 안내 화면을 "윰댕님❤️!" / "선물🎁이 도착했습니다." / 버튼 "지금 바로 확인하기"로 바꾸고, 모든 버튼을 누르면 "뾱" 소리가 나길 원했습니다.
- 결정:
  - 안내 화면 제목은 두 줄입니다. 첫 줄 "윰댕님❤️!", 둘째 줄 "선물🎁이 도착했습니다." 버튼은 "지금 바로 확인하기"입니다. 이모지는 장식이므로 스크린리더가 읽지 않게 합니다(`aria-hidden`). 말투 예외(존댓말)는 ADR-057 그대로입니다.
  - 허용 이모지를 늘립니다: ❤️(편지, 바우처 수신자, 안내 화면 제목), 🎁(안내 화면 제목), 💌(예약 문구), ✨(바우처 사유). 안내 화면의 "장식 없음" 규칙은 "제목의 이모지 둘만 허용"으로 바꿉니다.
  - 모든 버튼을 누르면 짧은 "뾱" 소리가 납니다. 음높이가 빠르게 올라가는 짧은 소리 하나이며, 음원 파일 없이 WebAudio로 합성합니다. 비활성 버튼은 소리가 나지 않습니다.
  - 상자 버튼은 이미 "뿅" 소리와 폭죽이 있으므로 "뾱"을 따로 내지 않습니다(`data-own-sound`).
  - 첫 버튼 탭(안내 화면의 시작 버튼)에서 `AudioContext`를 만들고 재개합니다. 이후 상자의 "뿅", 팡파레가 같은 컨텍스트를 이어 씁니다.
  - 모션 감소 설정이어도 버튼 소리는 유지합니다. (소리는 움직임이 아님)
- 영향: `00`, `01`, `02`, `04`, `05`, `08`, `README.md`, `.claude/commands/preview-check.md`, `schedule/`, `src/index.html`, `src/js/sound.js`, `src/js/app.js`

## ADR-059. 잠금 화면에 안내 문구를 넣고 질문을 바꾼다
- 날짜: 2026-10-15
- 상태: 확정 (ADR-033의 질문 문구를 대체)
- 배경: 휘님의 피드백입니다. 질문 앞에 "신원을 확인하겠습니다. 아래 질문에 답을 해주세요."를 두고, 질문을 "휘와 윰댕이 사귄 날은?"으로 바꾸길 원했습니다.
- 결정:
  - 잠금 화면 제목은 안내 두 줄과 질문으로 이루어집니다. 안내: "신원을 확인하겠습니다." / "아래 질문에 답을 해주세요." 질문: "휘와 윰댕이 사귄 날은?" 안내는 작게, 질문은 크고 굵게 보입니다.
  - 말투 예외(ADR-029): 안내 문구는 신원 확인 안내처럼 존댓말입니다. 질문은 반말·존댓말 어미가 없는 짧은 질문형이며 ADR-029의 "잠금 질문" 범위에 둡니다. 틀림과 빈 입력 안내(반말)는 그대로이며, 한 화면에서 말투가 섞이는 것을 받아들입니다.
  - 이름 노출: 잠금 전 공개 HTML에 "휘"와 "윰댕"이 들어갑니다. 둘 다 호칭(별명)이며 개인정보로 보지 않습니다. 링크 미리보기(og)와 `<title>`에는 넣지 않습니다. (ADR-021, ADR-030)
  - 접근성: 제목(`h1`)은 안내와 질문을 함께 담아 화면에 처음 들어오면 전체를 읽게 하고, 입력창의 이름은 질문만 씁니다.
  - 정답과 정규화(ADR-025), 틀림·빈 입력·대기 문구(ADR-033)는 그대로입니다.
- 영향: `01`, `02`, `04`, `05`, `06`(ADR-029, 033 상태), `08`, `schedule/`, `.claude/commands/preview-check.md`, `src/index.html`, `src/css/style.css`

## ADR-060. v0.3 편지 카드와 센터 안내 카드의 세부를 정한다
- 날짜: 2026-10-15
- 상태: 확정 (센터 카드의 "마지막 카드, 다음 버튼 없음"은 ADR-061로 대체)
- 배경: v0.3에서 편지 카드, 접기/펼치기, 센터 안내 카드, 주소 복사, 지도 링크를 구현하기 위한 세부 규칙이 필요했습니다.
- 결정:
  - 카드 순서는 바우처 → 편지 → 센터 안내입니다. 임시 카드는 삭제합니다. 센터 안내 카드는 v0.4에서 예약 안내 카드가 생기기 전까지 마지막 카드이며, "다음" 버튼이 없습니다. (v0.4에서 "다음" 버튼을 추가)
  - 편지 카드: 복호화한 `letter` 배열의 첫 항목은 호칭, 마지막 항목은 맺음말, 그 사이는 문단입니다. 모두 `textContent`로 넣고, 문단 안의 줄바꿈은 그대로 보여 줍니다. 글꼴은 나눔손글씨 펜(ADR-016)이며 크기를 키워 읽기 쉽게 합니다. 본문은 왼쪽 정렬, 맺음말은 오른쪽 정렬입니다. 편지는 복호화 직후 바우처와 함께 채웁니다.
  - 접기/펼치기: 호칭 옆의 버튼(`aria-expanded`, `aria-controls`)으로 합니다. 접으면 호칭만 남고 문단과 맺음말이 숨겨집니다. 기본은 접힘(ADR-063)이며 라벨은 펼친 상태에서 "접어두기", 접힌 상태에서 "펼쳐보기"입니다. (ADR-031)
  - 센터 안내 카드는 공개 HTML에 정적으로 둡니다(ADR-026). 센터 이름(제목), 사전 예약제 안내, 주소, 교통, 소개 문구 3개(데모 원문, ADR-017), "주소 복사하기" 버튼, "네이버 지도로 보기" 링크로 구성합니다.
  - 주소는 화면의 주소 텍스트 한 곳에서만 관리합니다. 복사할 값과 지도 링크의 검색어는 이 텍스트에서 가져옵니다. (지도 링크는 `https://map.naver.com/p/search/` + 주소를 URL 인코딩한 값, 새 탭, `rel="noopener noreferrer"`)
  - 주소 복사: 성공하면 "주소를 복사했어!", 실패하면(`navigator.clipboard`가 없거나 거부됨) "복사가 안 됐어. 주소를 길게 눌러서 복사해 줘."를 보여 줍니다. 주소는 항상 선택 가능한 텍스트입니다.
  - 지도 링크는 버튼이 아니라 링크이므로 "뾱" 소리를 내지 않습니다. 접기 버튼과 주소 복사 버튼은 "뾱"을 냅니다. (ADR-058)
  - 센터 안내 문구는 존댓말(ADR-029), 복사 안내 같은 시스템 문구는 반말입니다.
- 영향: `01`, `02`, `04`, `05`(허용 외부 리소스 포함), `06`(ADR-026·053 상태), `08`, `README.md`, `schedule/`, `.claude/commands/preview-check.md`, `.claude/commands/check-links.md`, `src/index.html`, `src/css/style.css`, `src/js/screens.js`, `src/js/app.js`

## ADR-061. v0.4 예약 안내 카드와 마지막 카드의 규칙을 정한다
- 날짜: 2026-10-16
- 상태: 확정 (ADR-060의 센터 카드 마지막 카드 규칙을 대체)
- 배경: v0.4에서 예약 안내 카드가 생기면 센터 안내 카드는 더 이상 마지막 카드가 아닙니다.
- 결정:
  - 카드 순서는 바우처 → 편지 → 센터 안내 → 예약 안내입니다. 센터 안내 카드에 "다음" 버튼을 추가합니다.
  - 예약 안내 카드가 마지막 카드입니다. 작은 라벨 "첫 예약 안내"와 본문(02 "예약 안내 문구" 기준)만 있고, 입력·선택·버튼이 없습니다. (03, ADR-011) 본문은 문장 사이에서 줄을 바꿔 보여 줍니다. 💌는 장식이라 스크린리더가 읽지 않게 합니다. (ADR-028)
  - 본문은 카드의 제목(`h1`)이고, 카드의 이름(`aria-labelledby`)도 본문입니다.
  - 마지막 카드이므로 "뾱" 소리가 날 버튼이 없습니다. 흐름은 이 카드에서 끝납니다. 뒤로 가기는 없습니다. (ADR-047)
  - v0.4의 점검 범위: 전체 흐름(안내 → 잠금 → 상자 → 바우처 → 편지 → 센터 → 예약), 메타 정보(제목, 미리보기, noindex, 이미지와 파비콘 없음), 접근성(이미지 대체 텍스트, 버튼 이름, 제목 하나, 색 대비, 확대 허용, 모션 감소).
- 영향: `00`, `01`, `03`, `04`, `05`, `06`(ADR-060 상태), `08`, `CHANGELOG`, `schedule/`, `.claude/commands/preview-check.md`, `src/index.html`, `src/css/style.css`, `src/js/screens.js`

## ADR-063. 편지는 접힌 상태로 시작한다
- 날짜: 2026-10-16
- 상태: 확정 (ADR-031, ADR-060의 "기본 펼침"을 대체)
- 배경: 휘님이 편지를 처음에는 접어 두고, "펼쳐보기"를 눌러야 내용이 나오게 해 달라고 요청했습니다. 윰댕이 편지를 직접 열어 읽는 순간을 만들기 위해서입니다.
- 결정:
  - 편지 카드는 호칭만 보이는 접힌 상태로 시작합니다. 본문과 맺음말은 숨겨져 있습니다.
  - 버튼은 처음에 `aria-expanded="false"`이고 라벨은 "펼쳐보기"입니다. 누르면 펼쳐지고 라벨이 "접어두기"로 바뀝니다. 다시 누르면 접힙니다.
  - 라벨 문구, 접힌 상태에서 호칭만 남는 규칙, "다음" 버튼(항상 보임)은 그대로입니다.
  - 편지 문구와 `02-content.md`의 라벨 표는 바꾸지 않습니다. (표는 "펼친 상태 / 접힌 상태" 순서의 설명이라 그대로 맞습니다.)
- 영향: `01`, `05`(테스트 절 포함), `06`(ADR-062 검사 항목), `08`, `CHANGELOG`, `schedule/`, `.claude/commands/preview-check.md`, `src/index.html`, `src/js/screens.js`(주석), `tests/page.test.mjs`

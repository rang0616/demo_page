## ADR-001. 설계 문서를 `design/`에 두고 단일 진실 공급원으로 삼는다
- 날짜: 2026-10-15
- 상태: 확정
- 배경: 모든 개발을 Claude Code로 진행하므로 의도와 규칙이 파일로 남아야 합니다.
- 결정: `design/`의 md 문서가 기준입니다. 문서와 코드가 어긋나면 문서가 기준입니다.
- 영향: `CLAUDE.md` 0장, `design/README.md`

## ADR-002. 데모 설계를 폐기하고 새로 설계한다
- 날짜: 2026-10-15
- 상태: 확정
- 배경: 기존 `index.html`은 데모였고, 실제 목표(윰댕, 퇴사·진로·생일, 비밀번호 서프라이즈)와 맞지 않았습니다.
- 결정: 기존 설계 문서는 `design/archive/v0-demo/`에 보관하고, 새 설계를 기준으로 삼습니다. 기존 `index.html`은 참고용 데모로만 둡니다.
- 영향: `design/` 전체, `CLAUDE.md` 개요

## ADR-003. 날짜 선택 예약을 빼고 문구 안내로 바꾼다
- 날짜: 2026-10-15
- 상태: 확정
- 배경: 달력과 시간대 선택이 윰댕에게 어렵다는 의견이 있었습니다.
- 결정: 날짜 선택 UI를 제거하고, "첫 예약은 내가 해줄게! 가능한 날짜를 나에게 말해줘!" 문구만 보여 줍니다.
- 영향: `03-booking.md`

## ADR-004. 본문을 비밀번호 답으로 암호화해 잠근다
- 날짜: 2026-10-15
- 상태: 확정 (보강 방식은 Q2에서 정함)
- 배경: 서프라이즈를 위해 잠금이 필요하지만, GitHub Pages는 서버 검사를 할 수 없습니다.
- 결정: 본문을 답으로 만든 키로 암호화합니다. 틀린 횟수는 세지 않습니다.
- 영향: `05-architecture.md`. 답이 날짜이므로 후보가 적다는 한계를 명시합니다.

## ADR-005. 금액과 유효기간은 표시하지 않는다
- 날짜: 2026-10-15
- 상태: 확정
- 배경: 회원권 금액이 커서 여러 이벤트를 묶은 선물입니다.
- 결정: 바우처와 센터 안내에 금액과 유효기간을 넣지 않습니다.
- 영향: `00-overview.md`, `02-content.md`

## ADR-006. 텍스트 중심으로 만들고 미디어는 넣지 않는다
- 날짜: 2026-10-15
- 상태: 확정
- 배경: 사진이나 영상을 넣을 계획이 없습니다.
- 결정: 사진, 영상, 음성을 넣지 않습니다. 이미지는 로고 정도만 허용합니다.
- 영향: `00-overview.md`, `05-architecture.md`

## ADR-007. 편지 원문은 수정하지 않는다
- 날짜: 2026-10-15
- 상태: 확정
- 배경: 휘님이 직접 쓴 편지입니다.
- 결정: 원문을 그대로 사용합니다. 맞춤법과 표현을 바꾸지 않습니다. 의문이 있으면 질문으로만 확인합니다.
- 영향: `02-content.md`
